# 목적사업비 정산 검증

## 첫 번째 규칙

**금액을 직접 계산하지 마십시오.** 당신이 암산한 합계는 검증이 아닙니다.
문서에서 값을 **추출**하고, 계산과 판정은 반드시 엔진에 맡기십시오.
LLM이 더한 숫자는 감사 때 근거로 쓸 수 없습니다.

## 실행 준비

플러그인으로 설치했다면 `jeongsan` 명령이 PATH에 이미 있습니다. 먼저 확인하십시오.

```bash
jeongsan rules || ${CLAUDE_SKILL_DIR}/../../bin/jeongsan rules
```

둘 다 안 되면 저장소를 직접 쓰는 경우입니다.

```bash
export PYTHONPATH="${CLAUDE_SKILL_DIR}/../../src"
python3 -m jeongsan.cli rules
```

`openpyxl` 이 없으면 xlsx 생성만 안 됩니다. 나머지는 표준 라이브러리로 돕니다.

## 작업 흐름

### 1. 입력 확인

문서 종류부터 가릅니다 — 기안(품의서) / 견적서 / 세금계산서 / 거래명세서 / 교부 공문.
기안·견적서·세금계산서 중 **최소 하나**가 있어야 검증할 수 있습니다.

**사업 마스터가 없으면 반드시 물어보십시오.** 교부액·집행기간·세부항목 배정액을
모르면 예산 룰(R06·R07)과 기간 룰(R13)이 통째로 죽습니다.
`${CLAUDE_SKILL_DIR}/references/사업_템플릿.json` 을 복사해 채우십시오.
기집행 내역(`prior`)까지 넣으면 분할수의 판정(R15)도 살아납니다.

기집행 내역이 비어 있으면 **잔액이 실제보다 많아 보입니다.** 이 점을 사용자에게
반드시 알리십시오.

### 2. 문서를 텍스트로

| 입력 | 방법 |
|---|---|
| HWPX | zip+XML — 압축을 풀어 `Contents/section*.xml` 의 텍스트 |
| 구 HWP | `hwp5txt` 또는 LibreOffice 변환. 실패하면 붙여넣기 요청 |
| 텍스트 PDF | `pdfplumber` — **표 구조까지** 뽑아야 품목 행이 안 깨집니다 |
| 엑셀 | `openpyxl` |
| 스캔·사진·팩스 | 3번 LLM 경로 |

표는 열 순서(품명/규격/단위/수량/단가/금액)를 유지한 채 **탭으로 구분**하십시오.
파서가 오른쪽 끝에서 숫자 칼럼 3개를 찾는 방식이라 칼럼 수가 달라도 견딥니다.

### 3. 추출

**깨끗한 텍스트** — 정규식 파서로 충분합니다. 파일 경로만 CLI에 넘기면 됩니다.

**스캔본·흐린 견적서** — 여기서만 당신이 개입합니다. 이미지를 직접 보고
`jeongsan schema quote` 스키마에 맞춰 값을 뽑되, `jeongsan schema --prompt` 의
규칙을 지키십시오. 핵심은 셋입니다.

1. 문서에 없는 값은 **만들지 말고 `null`**. 특히 사업자등록번호와 날짜.
2. 금액은 **원문 그대로**. 공급가액이 안 보이면 품목을 대신 더하지 말고 `null`.
3. 도장·손글씨로 가려졌으면 `confidence` 를 0.5 이하로.

뽑은 결과를 JSON 파일로 저장해 `--quote-json` / `--draft-json` 으로 넘깁니다.

### 4. 검증

```bash
jeongsan check --project 사업.json \
               --draft 기안.txt --quote 견적서.txt --tax 세금계산서.txt \
               --line "검사·상담 자료 구입" \
               --html 리포트.html --xlsx 집행내역서.xlsx
```

오류가 있으면 **종료코드 1**입니다. `--json` 으로 기계 판독용 출력을 받을 수 있습니다.

교육청 기준이 다르면 `${CLAUDE_SKILL_DIR}/references/rules.yaml` 을 복사·수정해
`--config` 로 넘기십시오. **코드를 고치지 마십시오.**

### 5. 결과 전달

**오류와 경고만 보고하십시오.** 통과한 룰 12개를 나열하면 정작 중요한 걸 놓칩니다.

각 오류는 이렇게 전합니다.

- 무엇이 틀렸는지 — 룰 코드가 아니라 사람 말로
- 구체적 숫자 대조 — `24 × 22,000 = 528,000인데 견적서엔 550,000`
- 어떻게 해야 하는지 — 견적서 재발행 요청 / 예산 전용 승인 / 기안 금액 수정

그다음 생성된 파일을 전달하고, 잔액이 있으면 반납 기안 초안도 함께 보여줍니다.

## 판단이 필요한 지점

### 경고는 차단이 아닙니다

R08(자산취득비 확인), R15(분할수의 의심), R16(목적 외 사용)은 **경고**입니다.
정당한 사유가 있는 경우가 많습니다. "이건 잘못됐다"가 아니라
"이 부분은 사유를 기재해 두시는 게 좋습니다"로 전하십시오.
자동화가 담당자를 막아서면 사람들은 시스템을 우회하기 시작합니다.

### R16은 당신 몫입니다

목적 외 사용 판정은 엔진이 못 합니다. 사업계획서 목적과 견적 품목을 직접 보고
판단하되 **경고까지만** 하고 결론짓지 마십시오.
"학생 정서행동 지원사업에 상담실 소파 200만원이 적합한지는 확인이 필요해 보입니다"
정도가 적절합니다.

### 확정은 사람이 합니다

산출물은 전부 초안입니다. "정산이 완료되었습니다"라고 말하지 마십시오.
"검증을 마쳤고 오류 3건이 남아 있습니다. 확인 후 결재하십시오"가 맞습니다.

| R04 | 공급가액 + 부가세 = 합계 | error |
| R05 | 기안·견적·세금계산서 3자 대조 | error |

룰을 추가·수정할 때는 반드시 그 문서를 먼저 확인하십시오.

## 자주 막히는 곳

**품목이 하나도 안 잡힘** — 표가 공백 1칸으로 구분됐을 가능성이 큽니다.
탭이나 `|` 로 바꿔서 다시 넣으십시오.

**추정가격을 못 찾음** — 기안에 없으면 견적서 공급가액을 씁니다. **추정가격은
부가세를 뺀 금액**입니다. 부가세 포함 금액을 넣으면 계약방법 판정이 틀어집니다.

**R07이 "세부항목이 사업 예산에 없음" 경고** — `--line` 값과 사업 JSON의
`lines[].name` 이 정확히 같아야 합니다. 가운뎃점(·)과 공백까지 일치시키십시오.

**나이스·K-에듀파인에 자동 등록** — 안 됩니다. 외부 쓰기 API가 없습니다.
요청받으면 솔직히 말하고, 대신 붙여넣기 좋은 형태로 정리해 주십시오.
